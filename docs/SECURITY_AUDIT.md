# Phase 6 security audit

Phase 7 release preparation adds explicit HTTPS production extension targets, matching host/CSP policy and API-origin binding for stored device credentials; separate release output preserves local builds. Server binding/proxy trust are explicit and reject boolean/hop-count/all-address trust. Production HSTS omits `includeSubDomains`; development emits no HSTS. A new native Chrome check and unit regressions passed. MIT licensing, staged/current/history secret checks, reviewed fixture screenshots and deployment risk controls are documented in [RELEASE_READINESS.md](RELEASE_READINESS.md). The review below records the original Phase 6 scope; remote HTTPS/container acceptance remains unexecuted.

Scope: local source review, unit tests, real PostgreSQL/HTTP integration tests, actual Chrome extension workflow, packaging and environment-handling checks. This is an engineering audit of exercised boundaries, not an independent penetration test, dependency-vulnerability certification or production approval. No account data was deleted and no secrets were printed. A local Phase 5 checkpoint (`a97e5e0`) excludes private environment files and generated profiles.

## Regression and operational safeguards

`npm test`, `npm run test:integration`, `npm run test:browser-sync`, `npm run verify:extension` and `npm run test:smoke` exercise these paths. Integration/benchmark preflight verifies actual application/test identities before writes. Only uniquely owned test fixtures are removed; application connections perform baseline reads. Migrations add nullable provenance columns and seeds update only reference rows. Browser temporary-directory cleanup checks absolute containment before deletion.

The HTTP benchmark uses a fixed, guarded temporary index only in the test database and drops only the index it created. Production indexes were left unchanged after measurements did not justify the proposed addition. No input-driven SQL construction was introduced. CI adds report freshness and native-browser checks; remote CI execution is not claimed from local runs.

Dependency versions were preserved; no new runtime dependencies or extra browser permissions were needed. Registration conflicts still reveal an existing email address; this known enumeration tradeoff is documented rather than presented as solved. Scheduled session/code/retention cleanup for inactive users, centralized rate limits, encrypted operational storage, TLS and production incident controls remain necessary before real deployment.
